# powerpoint-addons

PowerPoint (Mac) task-pane add-in "Victor Tools", button on the Home tab. One pane, no tabs: every button is in sight (details in each button's tooltip).
- **Code block** — paste code, pick language/theme/size → syntax-highlighted JetBrains Mono text box (VS Code Dark+/Light+ colors).
- **Selected picture → Invert** — select a picture → "Invert selected image" replaces it with its negative (black ↔ white, alpha kept). Needs PowerPointApi 1.10 (Mac 16.105+).
- **Selected picture → Remove background** — cuts the subject out of the selected picture with BiRefNet on the Mac's GPU, trimmed to the subject and placed where the subject was. Moved here from Victor Addons' ⌘⇧V bezel (2026-10-06): PowerPoint is the only place it's needed.
- **Selected picture → Remove watermark** — any picture with a stock watermark (text or logo, tiled or not, even fragments of a few letters): Claude finds it, LaMa paints it out, ~25 s. Claude sees but can't draw, so `bg-remove/watermark.py` splits the job: the picture goes to Claude in overlapping 2×2 tiles (`claude -p` on the subscription, opus at effort low; whole-picture asks missed most small fragments, and macOS Vision OCR read nothing on gray-on-black); inside each box only thin strokes that stay inside it and have the watermark's tone are masked, so the art under the box survives (whole boxes erased a barbed wire; strokes alone erased a hand's outline crossed by diagonal "shutterstock"); big-lama (TorchScript on MPS, downloaded once to `~/Library/Caches/powerpoint-addons/`, sha256-pinned) paints the holes, color and alpha separately. A second look catches what the first one missed. One process per click (`watermark.js`), log in `/tmp/powerpoint-addons-watermark.log`; `WATERMARK_DEBUG=<dir>` saves each pass's boxes and mask.
- **Selected picture → Crop border** — cuts off the useless border: per side, the flat band of transparent, white, black or any one color (`web/crop.js`, in the pane, no server). The rest stays exactly where it was on the slide. Only the outer band goes, so a header bar under a margin or a slowly changing sky stays; click again to take the next band. A band counts as one color within 16/255 per channel, which covers JPEG noise but not a speck on the border.
- **Animated group → Add selection** — select an animated group plus the shapes to add: they join the group, which keeps its id, so its animation and its place in the build order stay. Office.js has no animation API and ungroup + group makes a new id the animation doesn't know, so the pane exports the slide (`exportAsBase64`, PowerPointApi 1.8), `web/regroup.js` moves the shapes inside the `<p:grpSp>` in the XML (into the group's own scaled coordinate space), and the rebuilt slide replaces the original (`insertSlidesFromBase64` after it, then delete). The added shapes lose their own effects (PowerPoint animates only top-level shapes); placeholders, tables and rotated groups are refused. Tests: `npm test`.
- **Links → Blue underline on links** — on the selected slides (select many in the thumbnails for a whole deck), every hyperlink keeps its own text color and font and only its underline turns blue. It writes what PowerPoint's own Font › Underline color writes on a link — `u="sng"`, `<a:uLnTx/>`, `<a:uFill>` in theme color `tx2`, and the 2018 `hlinkClr val="tx"` extension that stops the link from repainting the text in the theme's hyperlink color — copied from slides styled by hand. Office.js has neither, so it goes through the same export → edit XML (`web/links.js`) → reinsert path as the animated group; slides without changes aren't rebuilt.
- **Text-heavy slides** — ranks slides by word count; click to jump.
- **🔤 Font bar** — the selection's font name and size in PowerPoint's title bar, right of the deck's name, editable: click a box → its list opens (fonts drawn in their own face, Office's bundled fonts included), with the selected text (or the word at the caret) drawn on the right of each font, in that font; type to filter by substring, ↑/↓, Return or click to apply, Esc to give up. Office for Mac lets only buttons into the Quick Access Toolbar, never the Font / Font Size boxes, so it's a native panel (`font-bar/FontBar.swift`, built by `font-bar/build.sh`) that `server.js` starts and keeps alive, glued to PowerPoint's front window by `CGWindowList` frames (no permissions) and hidden in slide show / full screen / other apps. Values come from the pane (`web/fontbar.js`: selection-change event + a 600 ms poll, since the ribbon's own Font Size box fires no event), so it works only in decks where Victor Tools is open (see 📌 below). Selected text → that text; a caret or shapes selected as objects → all text of those shapes. Hub and protocol in `font-bar.js`, log in `/tmp/powerpoint-addons-font-bar.log`. To iterate on its look without the mouse: `font-bar/.build/font-bar --preview DIR dark|light [typed|size]` draws it off screen, list open, into `DIR/bar.png` + `DIR/list.png`.

## Opening with the deck (📌 `pin-deck.py`)
A sideloaded add-in gets no ribbon button of its own: it has to be opened from Home › Add-ins › Developer Add-ins, in every deck, every session — only add-ins deployed by a Microsoft 365 admin load everywhere by themselves. `./pin-deck.py DECK.pptx …` tags a deck so PowerPoint opens the pane with it from then on (`visibility="1"` on the add-in's pane in `ppt/webextensions/taskpanes.xml`, plus the parts if the deck has none). The Office.js way, `Office.AutoShowTaskpaneWithDocument` from the pane, writes `visibility="0"`, which PowerPoint for Mac 16.114 ignored (2026-11-03: same deck reopened, no pane; `visibility="1"` loaded it every time). The deck must be closed in PowerPoint; the original goes to `~/Library/Caches/powerpoint-addons/pinned-backups/` first. The manifest's `TaskpaneId` is `Office.AutoShowTaskpaneWithDocument`, which the tag points at.

## How it's wired
- `web/` static task pane, served over HTTPS by `server.js` on `https://localhost:44344` (Office loads add-ins only over https).
- `certs/` self-signed localhost cert (git-ignored), trusted in the login keychain for SSL.
- `manifest.xml` sideloaded by copying to `~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/wef/victor-tools.xml`.
- Requires PowerPointApi 1.5.
- 🧽 Watermark removal shares the `bg-remove` venv (torch) but not its warm process: torch and LaMa load in ~3 s, small next to Claude's ~10 s per pass.
- ✂️ Background removal can't run in the pane: `server.js` answers `POST /bg-remove` (PNG in, trimmed PNG + its box out) through `bg-remove.js`, which keeps `bg-remove/cutout_server.py` (BiRefNet, PyTorch MPS fp16, edge bleed) warm over a JSON-lines pipe. It lives as long as PowerPoint does: a 30 s `pgrep` watcher in `server.js` loads it when PowerPoint is running and stops it when PowerPoint quits (~5 GB; ~10 s cold, ~1 s warm). A 30-min idle timeout came first and missed: the clicks come hours apart, so nearly every one hit a cold model. `uv run --project bg-remove` builds the venv on first use (needs `/opt/homebrew/bin/uv`); its stderr goes to `/tmp/powerpoint-addons-bg-remove.log`. Deps and the Hub commit of `ZhengPeng7/BiRefNet` are pinned.

## Run
Installed as LaunchAgent `ro.victorrentea.powerpoint-addons` (source: `launchagent.plist`), starts at login, log in `/tmp/powerpoint-addons.log`.
Restart after editing `server.js`: `launchctl kickstart -k gui/$(id -u)/ro.victorrentea.powerpoint-addons`.
Edits under `web/` need no restart (served with `no-store`), just reopen the pane.
